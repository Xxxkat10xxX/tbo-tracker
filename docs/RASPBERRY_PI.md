# Сервер tbo-tracker на Raspberry Pi 5 (8 ГБ)

Raspberry Pi работает как постоянный сервер в локальной сети. Пользователи открывают tbo-tracker в браузере на
любом компьютере, планшете или телефоне по адресу `http://tbo-tracker.local`.

Вся логика выполняется на Raspberry Pi:

- расчёт наработки и остаточного ресурса;
- регламенты и уведомления, в том числе рассылка в Telegram и на webhook;
- перестановки узлов одной транзакцией;
- автономные полёты в симуляторе;
- демо-сценарии;
- резервные копии.

Браузер только показывает данные и передаёт действия пользователя. Уведомления формируются и рассылаются,
даже когда сайт никто не открыл.

## Выбранный способ настройки и почему

| Этап | Способ | Почему так |
|---|---|---|
| Подготовка ОС | **Raspberry Pi Imager** (программа с окнами на вашем ПК) → **Raspberry Pi OS Lite (64-bit)** | Imager сразу задаёт имя хоста, пользователя, Wi-Fi, часовой пояс и SSH. Монитор и клавиатура к Pi не нужны. Lite — без рабочего стола: больше памяти и меньше обновлений, сервер не тратит ресурсы на графику. |
| Установка tbo-tracker | **Одна команда по SSH**: `sudo ./deploy/raspberry-pi/install.sh` | Воспроизводимо, без ручных шагов, можно повторить на другой плате. Скрипт можно перезапускать: обновит код и сохранит данные и настройки (`/etc/tbo-tracker/tbo.env`). С параметрами режима (`--https`, `--port`, `--demo`) установщик перезаписывает свои ключи, а остальные настройки — например, `TBO_DRONE_*` — переносит. |
| Ежедневное администрирование | **Веб-страница «Сервер»** в самом tbo-tracker | С любого устройства: температура, питание, память, диск, адреса, резервные копии (создать / скачать / восстановить), каналы уведомлений (Telegram, webhook). |
| Обслуживание и аварийные случаи | **Утилита `tbo-ctl`** по SSH | Пароль, порт, обновление, журналы, восстановление, когда веб-интерфейс недоступен. |

Почему не так:

- **Рабочий стол на Pi** — лишняя нагрузка и обслуживание; сервер не нуждается в мониторе.
- **Docker** — дополнительный слой, тратит память и место на карте. Нативная служба systemd проще в диагностике и запускается сама после включения.

  Docker при этом работает (образ `python:3.12-slim` есть для arm64), см. раздел «Альтернатива: Docker».

## Что понадобится

| | Рекомендация |
|---|---|
| Плата | Raspberry Pi 5, 8 ГБ (хватит и 4 ГБ: сервис занимает ~150 МБ ОЗУ) |
| Питание | **Официальный блок питания 27 Вт USB-C.** При слабом БП страница «Сервер» покажет «пониженное напряжение» |
| Охлаждение | Active Cooler (официальный) или корпус с вентилятором |
| Накопитель | **NVMe SSD через M.2 HAT+** или USB 3 SSD — для круглосуточной работы. microSD (A2, от 32 ГБ) годится для испытаний; страница «Сервер» предупредит, если данные на карте |
| Сеть | Ethernet (надёжнее Wi-Fi). Закрепите IP за Pi в роутере (DHCP-резервирование) |

## 1. Подготовка ОС (на вашем компьютере)

1. Установите Raspberry Pi Imager: <https://www.raspberrypi.com/software/>.
2. **Устройство:** Raspberry Pi 5. **ОС:** Raspberry Pi OS (other) → **Raspberry Pi OS Lite (64-bit)**. **Накопитель:** ваша карта или SSD.
3. «Далее» → «Изменить настройки»:
   * имя хоста: `tbo-tracker` (адрес будет `http://tbo-tracker.local`);
   * имя пользователя и пароль (например `pi` и надёжный пароль);
   * Wi-Fi — если не используете кабель;
   * часовой пояс (нужен для резервных копий «в 3 часа ночи»);
   * вкладка «Службы» → **включить SSH** (по паролю или ключу).
4. Запишите, вставьте в Pi, подключите сеть и питание. Через 1–2 минуты Pi в сети.

## 2. Установка tbo-tracker (по SSH)

С вашего компьютера (Windows 10/11 — PowerShell, macOS/Linux — терминал):

```bash
ssh pi@tbo-tracker.local
```

На Raspberry Pi:

```bash
sudo apt update && sudo apt install -y git
```

```bash
git clone https://github.com/Xxxkat10xxX/tbo-tracker.git && cd tbo-tracker
```

```bash
sudo ./deploy/raspberry-pi/install.sh --https
```

Установщик (3–5 минут) выполняет следующее:

- ставит системные пакеты: `python3-venv`, `avahi-daemon` для адреса `*.local`, `rsync`; с `--https` — ещё `caddy`;
- создаёт системного пользователя `tbo` без входа в систему;
- копирует приложение в `/opt/tbo-tracker`;
- создаёт виртуальное окружение Python и ставит зависимости точных версий из `requirements.lock`;
- **без интернета на Pi** ставит зависимости из готовых пакетов `~/tbo-tracker/wheels`: их скачивает и привозит
  `deploy/field/deploy.sh` с компьютера (списки с SHA-256 — `deploy/raspberry-pi/offline/`, для Python 3.11 и 3.13;
  после изменения `requirements.lock` их обновляет `python3 deploy/raspberry-pi/offline/make_lists.py`);
- записывает настройки в `/etc/tbo-tracker/tbo.env` — **паролей там нет**;
- создаёт базу в `/var/lib/tbo-tracker` (каталог доступен только сервису);
- **спрашивает пароль администратора** — ввод скрыт, пароль нигде не сохраняется в открытом виде;
- с `--https` настраивает Caddy: адрес `https://tbo-tracker.local`, сертификат собственного центра сертификации;
- регистрирует службу `tbo-tracker` с автозапуском и проверяет, что она отвечает.

В конце установщик выводит адрес:

```
==> tbo-tracker работает
   Откройте: https://tbo-tracker.local
   Вход: admin и заданный вами пароль. Сотрудников добавьте в разделе «Пользователи».
```

Параметры установщика:

| Параметр | Значение |
|---|---|
| `--https` | HTTPS через Caddy. **Рекомендуется:** без него пароли передаются по сети открыто |
| `--demo` | демо-данные, сценарии проверки и кнопка «Сбросить демо-данные» (для показа; в работе — без него) |
| `--admin ИМЯ` | имя первого администратора (по умолчанию `admin`) |
| `--port 8080` | порт без HTTPS (по умолчанию 80) |

Если установщик запущен не из терминала (например, скриптом), администратор не создаётся. В этом случае откройте сайт и введите одноразовый код настройки — он выводится командой `sudo tbo-ctl setup-code`.

**Доверие к сертификату HTTPS.** С `--https` браузер предупреждает о сертификате, пока на устройство не установлен корневой сертификат Caddy. Порядок:

1. Выполните `sudo tbo-ctl https-ca` — команда скопирует файл в домашний каталог.
2. Перенесите его на компьютер: `scp pi@tbo-tracker.local:tbo-tracker-root-ca.crt .`.
3. Установите как доверенный корневой сертификат:
   - Windows — двойной щелчок по файлу → «Установить» → «Доверенные корневые центры»;
   - macOS — «Связка ключей» → «Всегда доверять»;
   - Android и iOS — «Настройки» → «Безопасность» → «Установить сертификат».

> Если адрес `tbo-tracker.local` не открывается (в некоторых корпоративных сетях mDNS заблокирован),
> используйте IP-адрес из вывода установщика или из `sudo tbo-ctl status`.

## 3. Работа с сервером

### Страница «Сервер» (в меню слева)

* **Состояние:**
  - модель платы, температура процессора, загрузка, свободная память и место на диске;
  - тип накопителя;
  - питание и троттлинг по `vcgencmd`;
  - адреса для подключения;
  - время последней фоновой проверки и рассылки.

  Проблемы выводятся предупреждениями: пониженное напряжение, перегрев, данные на microSD, мало места.
* **Уведомления вне браузера:**
  - Telegram-бот;
  - webhook (POST JSON для диспетчерской, Mattermost, n8n и т. п.);
  - выбор категорий: предельный ресурс, просрочено, падения/столкновения, приближение;
  - периодичность проверки;
  - кнопка «Отправить тестовое сообщение».

  Telegram: создайте бота у @BotFather и напишите ему сообщение. `chat_id` найдите в ответе `https://api.telegram.org/bot<токен>/getUpdates`. Pi нужен доступ в интернет.
* **Резервные копии:**
  - ежедневно в заданный час (по умолчанию 03:00), хранится 14 последних;
  - ручное создание, скачивание, загрузка .zip, восстановление.

  Копия — это zip с базой и загруженными фото. Перед восстановлением текущее состояние сохраняется автоматически.
  **Регулярно скачивайте копии на другой носитель.**

### `tbo-ctl` по SSH

| Команда | Что делает |
|---|---|
| `sudo tbo-ctl status` | служба, модель, температура, память, диск, данные, адреса, предупреждения |
| `sudo tbo-ctl logs` | журнал службы в реальном времени |
| `sudo tbo-ctl restart` / `stop` / `start` | управление службой |
| `sudo tbo-ctl backup` / `backups` | создать копию / список копий |
| `sudo tbo-ctl restore ИМЯ.zip` | восстановить (по имени из списка или путь к файлу); служба на это время останавливается |
| `sudo tbo-ctl update` | копия «перед обновлением» → `git pull` → переустановка с сохранением данных и настроек |
| `sudo tbo-ctl user list` | учётные записи |
| `sudo tbo-ctl user add ИМЯ [admin\|engineer\|viewer]` | создать пользователя (пароль — скрытый ввод, временный: сменить при первом входе) |
| `sudo tbo-ctl user passwd ИМЯ` | задать новый пароль, если забыт |
| `sudo tbo-ctl user unlock ИМЯ` | снять блокировку после неудачных попыток входа |
| `sudo tbo-ctl user disable ИМЯ` / `enable` | отключить / включить учётную запись |
| `sudo tbo-ctl setup-code` | одноразовый код первичной настройки (если учётных записей ещё нет) |
| `sudo tbo-ctl https-ca` | корневой сертификат HTTPS для установки на устройства |
| `sudo tbo-ctl port 8080` | сменить порт (без HTTPS) |
| `sudo tbo-ctl reset-demo` | пересоздать демо-данные (сначала делается копия) |
| `sudo tbo-ctl notify-test` | тестовое сообщение в Telegram / webhook |
| `sudo tbo-ctl uninstall [--purge]` | удалить службу (`--purge` — вместе с данными) |

### Где что лежит

| Путь | Содержимое |
|---|---|
| `/opt/tbo-tracker` | приложение и виртуальное окружение (только чтение для службы) |
| `/var/lib/tbo-tracker/tbo.db` | база SQLite (режим WAL) |
| `/var/lib/tbo-tracker/uploads` | загруженные фото бортов |
| `/var/lib/tbo-tracker/backups` | резервные копии |
| `/var/lib/tbo-tracker/server.json` | настройки страницы «Сервер» (каналы уведомлений, расписание копий) |
| `/etc/tbo-tracker/tbo.env` | адрес, порт, режим демо-данных, внешний адрес HTTPS (паролей нет) |
| `/etc/systemd/system/tbo-tracker.service` | служба systemd |

## Как устроен сервис

- **Служба systemd `tbo-tracker`.** Запускается при включении и перезапускается при сбое.
  - Работает от пользователя `tbo` без прав root. Порт 80 открывается через `CAP_NET_BIND_SERVICE`.
  - Изоляция: писать служба может только в `/var/lib/tbo-tracker`.
  - Ограничение памяти — 1 ГБ.
- **Один процесс uvicorn.** SQLite и фоновые задачи живут в одном процессе, поэтому не нужны ни cron, ни внешняя очередь.
  - Раз в минуту процесс пересчитывает уведомления и рассылает новые.
  - Раз в сутки делает резервную копию.
  - Для небольшого парка (десятки бортов, несколько пользователей) Pi 5 с запасом хватает: страница открывается за доли секунды.
- **Бережное отношение к накопителю:**
  - SQLite в режиме WAL с `synchronous=NORMAL`;
  - журнал запросов отключён, пишутся только предупреждения;
  - журнал systemd ограничен системой.
- **Доступ — по учётным записям.** Роли: администратор, инженер, наблюдатель. Пароли хранятся только как хеш Argon2id.
  - Сессии — в cookie HttpOnly / SameSite=Strict, при HTTPS ещё и Secure.
  - Защита от перебора и журнал аудита.
  - Подробно — [SECURITY.md](SECURITY.md).

## Безопасность

* Устанавливайте с `--https`: без шифрования пароли передаются по сети открыто. Страница «Сервер» предупреждает об этом.
* Давайте сотрудникам минимально нужную роль. Учётные записи уволенных отключайте сразу.
* Для доступа из интернета не открывайте порт на роутере — используйте VPN (WireGuard, Tailscale).
* Полное описание мер защиты — [SECURITY.md](SECURITY.md).
* Обновления ОС: `sudo apt update && sudo apt full-upgrade` раз в месяц.
* Файрвол (необязательно):

```bash
sudo apt install -y ufw && sudo ufw allow ssh && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw enable
```

## Обновление и перенос

* **Обновление tbo-tracker:** `sudo tbo-ctl update`.
* **Перенос на новую плату или SSD:**
  1. На старой плате: страница «Сервер» → скачать свежую копию.
  2. На новой плате: установить tbo-tracker (без `--demo`).
  3. «Сервер» → «Загрузить .zip» → «Восстановить».
* **PostgreSQL вместо SQLite** (большой парк, отдельный сервер): удобнее Docker — [DEPLOY.md](DEPLOY.md).
  Копия с Pi (SQLite) восстанавливается в PostgreSQL без преобразований: формат копий не зависит от СУБД.

## Неполадки

| Симптом | Что сделать |
|---|---|
| `tbo-tracker.local` не открывается | откройте по IP (`sudo tbo-ctl status`); проверьте `systemctl status avahi-daemon` |
| Сайт не отвечает | `sudo tbo-ctl status`, затем `sudo tbo-ctl logs` |
| «Пониженное напряжение» на странице «Сервер» | замените блок питания на официальный 27 Вт, уберите USB-устройства с большим потреблением |
| Высокая температура | установите Active Cooler, проверьте вентиляцию корпуса |
| Порт 80 занят другим сервисом | `sudo tbo-ctl port 8080` |
| Забыт пароль | `sudo tbo-ctl user passwd ИМЯ` (по SSH) или другой администратор в разделе «Пользователи» |
| «Слишком много неудачных попыток» | подождать 15 минут или `sudo tbo-ctl user unlock ИМЯ` |
| Браузер предупреждает о сертификате (HTTPS) | установите корневой сертификат: `sudo tbo-ctl https-ca` (раздел 2) |
| Telegram: «ошибка: …» в журнале уведомлений | проверьте токен, chat_id и доступ Pi в интернет; кнопка «Отправить тестовое сообщение» |

## Альтернатива: Docker

Docker работает на Pi 5 (arm64). Порядок:

1. Установите Docker: <https://docs.docker.com/engine/install/debian/>.
2. Дальше — по [DEPLOY.md](DEPLOY.md): `sh deploy/docker/init.sh`, затем `docker compose … up -d --build`, первый администратор — по коду настройки из `docker compose logs app`.

Утилита `tbo-ctl` и страница «Сервер» в части управления службой рассчитаны на установку через `install.sh`.

## Проверено

| Что | Как проверено |
|---|---|
| Готовые пакеты arm64 | Для всех зависимостей есть готовые пакеты под arm64 (`manylinux aarch64`) для Python 3.11 (Raspberry Pi OS Bookworm) и Python 3.13 (Trixie) — компилятор на Pi не понадобится |
| `install.sh` и `tbo-ctl` | Проверены целиком в Debian-контейнере (x86_64), `systemctl` заменён заглушкой: установка, код настройки, пользователи (добавление, пароль, разблокировка), копия, восстановление, обновление со старой версии. Скрипты проходят `shellcheck`, конфигурация HTTPS проверена валидатором Caddy |
| Автотесты | Проходят на свежих версиях библиотек — тех, что установщик ставит на Pi |
| На реальном Raspberry Pi 5 | Установка в рамках прототипа **не выполнялась**: при первом запуске проверьте вывод установщика и `sudo tbo-ctl status` |
