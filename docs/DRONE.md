# Полёт на реальном борту: Skyris Technic 6S (Orange Pi 5 Pro + PX4)

tbo-tracker отправляет миссию на дрон, запускает её по кнопке оператора, показывает полёт на карте и после
посадки сам импортирует журнал полёта. Наработка и циклы начисляются борту и установленным узлам, удары
по акселерометру попадают в мониторинг падений и столкновений, срабатывают напоминания ТО.

```
 tbo-tracker (сервер, Raspberry Pi / Docker)            дрон Skyris Technic 6S
 ┌───────────────────────────────┐   Wi-Fi    ┌───────────────────────────────────────────┐
 │ миссии · журнал · ТО           │◄──────────►│ Orange Pi 5 Pro: служба tbo-agent         │
 │ /api/drones (оператор)        │  HTTPS     │   ↕ ROS Noetic: MAVROS, simple_offboard    │
 │ /api/agent  (токен устройства)│            │ PX4 (полётный контроллер) ◄── пульт пилота │
 └───────────────────────────────┘            └───────────────────────────────────────────┘
```

* **Агент `tbo-agent`** (каталог `agent/`) работает на бортовом компьютере. Он сам обращается к серверу, поэтому
  на дроне не нужно открывать входящие порты. Агенту нужны только Python 3.8+ и ROS-пакеты, которые уже есть в образе Technic.
* **Связь:**
  - сервер узнаёт агента по **токену устройства**;
  - команды агент получает долгим опросом и доставляет на борт за секунду;
  - состояние и телеметрию агент присылает каждые 1–5 с.
* **Полётом управляет PX4.** Агент загружает план в контроллер, включает режим и следит за полётом.
  **Пульт пилота главнее**: переключение режима на пульте забирает управление (штатная функция PX4).

## 1. Что нужно

* Дрон с образом Technic для Orange Pi 5 Pro:
  - ROS Noetic, служба `technic`;
  - подключение к PX4 по UART или USB — `rostopic echo -n1 /mavros/state` показывает `connected: True`;
  - GPS с откалиброванным компасом;
  - настроенные failsafe (раздел 6).
* Сервер tbo-tracker и Wi-Fi, общий с дроном. Рекомендуется общий роутер: инструкция Skyris «Подключение к Wi-Fi
  сети», способ 1. Можно и так: сервер подключается к точке доступа дрона `technic-xxxx`, тогда адрес сервера будет
  в сети 10.42.0.x. Но в этом режиме одновременно работает только один дрон.
* В карточке борта в tbo-tracker — статус «В эксплуатации», обязательные узлы установлены, просроченных работ ТО нет.
  Иначе сервер не допустит борт к полёту.

## 2. Подключение борта (один раз)

1. **Выпустить токен.** Администратор: «Борты на связи» → **«+ Подключить борт»** → выбрать борт → «Выпустить токен».
   - Токен показывается **один раз**. В базе хранится только его хеш.
   - Одному борту соответствует одно подключение.
2. **Скачать агент.** Там же кнопка **«⇩ Агент для борта»** (`tbo-agent.tar.gz`). Скопируйте архив на борт:

   ```bash
   scp tbo-agent.tar.gz orangepi@АДРЕС_БОРТА:~
   ```

3. **Установить агент на борту** (`ssh orangepi@АДРЕС_БОРТА`):

   ```bash
   tar xzf tbo-agent.tar.gz && cd tbo-agent && sudo ./install.sh
   ```

   Установщик:
   - спросит адрес сервера, например `https://tbo.local` или `http://192.168.1.10:8000`;
   - спросит токен (**ввод скрыт**, токен сохраняется в `/etc/tbo-agent/token` с правами 600);
   - проверит связь с сервером и запустит службу `tbo-agent` (после `technic`).
4. **Проверить.** `journalctl -u tbo-agent -f` → «подключён к …: борт …». В «Бортах на связи» борт станет **«На связи»**:
   видны батарея, GPS, режим, версия агента и исполнитель.

Заменить токен (например, при утечке): «Новый токен» в tbo-tracker, затем `sudo ./install.sh --token` на борту.

## 3. Полёт (оператор, роль «Инженер» или «Администратор»)

1. **Открыть миссию.** «Миссии» → миссия с назначенным бортом. В правой колонке — панель **«Полёт на борту»**.
2. **«⇪ Отправить план на борт».** Миссия сохраняется. Сервер проверяет:
   - допуск борта по ТО и комплектности;
   - пределы реального полёта: высота ≤ `TBO_DRONE_MAX_ALT_M`, удаление ≤ `TBO_DRONE_MAX_DIST_M`.

   Затем агент на борту:
   - проверяет целостность плана (хеш) и то, что план для **этого** борта;
   - проверяет собственные пределы борта;
   - проверяет связь с контроллером, что моторы выключены, GPS (3D, спутников ≥ `min_sats`) и точку «дом»;
   - проверяет, что борт стоит **в точке взлёта миссии** (допуск `max_home_offset_m`) и заряд батареи достаточен;
   - загружает план в PX4 и **сверяет его обратным чтением**.

   Результат каждой проверки виден в панели. Если всё пройдено — **«Готов к старту»**.
3. **«▶ Старт».** Нужно подтвердить три пункта: зона взлёта свободна, пилот с пультом на месте, полёт разрешён.
   - Команда «Старт» живёт **15 секунд**: старая команда после обрыва связи не выполнится.
   - Перед стартом борт повторяет проверки и ещё раз сверяет план в контроллере. Если его поменяли, например
     из QGroundControl, старт отменяется.
4. **Полёт.**
   - На карте миссии видны положение борта и пройденный трек. В панели — режим PX4, высота, скорость, батарея,
     GPS, точка маршрута, сообщения PX4.
   - **«⌂ Вернуть домой»** (AUTO.RTL) срабатывает сразу. Если связь пропала, команда доставится при восстановлении,
     в течение 2 минут.
   - **«⤓ Посадить на месте»** (AUTO.LAND) — с подтверждением.
5. **После посадки** агент передаёт журнал, сервер импортирует его автоматически. В панели и в «Истории
   выполнения» появляется итог:
   - «Выполнена» или «Прервана»: возврат или посадка по команде, перехват пилотом;
   - длительность, путь, высота, номер импорта, начисленная наработка, события датчиков.

## 4. Исполнители плана (`/etc/tbo-agent/agent.conf` → `[vehicle] executor`)

| Исполнитель | Как летит | Когда выбирать |
|---|---|---|
| `mission` | План загружается в PX4 как миссия (`mavros/mission/push`): взлёт, скорость, точки с удержанием, возврат домой или посадка. Старт — AUTO.MISSION и арминг, как «Start Mission» в QGroundControl | Рекомендуется для GPS-полётов: полёт ведёт сам PX4, он виден в QGroundControl и продолжается при сбое бортового компьютера |
| `offboard` | Программа на борту по образцу Technic (раздел «Программирование автономного полёта»): `navigate(z, frame_id='body', auto_arm=True)` → `navigate_global` по точкам → AUTO.RTL или `land` | Если плагин миссий MAVROS отключён, или нужен полёт средствами simple_offboard |
| `auto` (по умолчанию) | `mission`, если в MAVROS есть сервисы миссии, иначе `offboard` | — |

В Technic часть плагинов MAVROS отключена (`plugin_blacklist` в `/home/orangepi/technic_ws/src/technic/technic/launch/mavros.launch`).
Чтобы работал `mission`, уберите из этого списка `waypoint` и перезапустите `sudo systemctl restart technic`.
Какой исполнитель выбран, видно в «Бортах на связи».

**Перехват управления пилотом.**
- В режиме `offboard` при переключении режима на пульте программа на борту немедленно прекращает работу и больше
  не отправляет борту команд.
- При сбое программы в воздухе исполнитель `offboard` переводит борт в AUTO.RTL.

## 5. Журнал и учёт

* **Что пишет агент:**
  - трек — 1 раз в секунду;
  - акселерометр |a| — 25 Гц, с сохранением пиков, чтобы сервер нашёл удары: падение или столкновение;
  - смена режимов, сообщения PX4, заряд в начале и в конце, достигнутые точки.
* **Время полёта** привязано к часам сервера. У Orange Pi без интернета часы могут быть неверными, поэтому агент
  сверяется с сервером при каждом обмене.
* **Журнал не теряется.** Сначала он сохраняется на борту (`/var/lib/tbo-agent/outbox`), потом передаётся.
  При отсутствии связи передача повторяется каждые 30 с. После перезапуска агента в полёте наблюдение продолжается;
  если агент перезапустился уже после посадки, журнал восстанавливается по контрольной точке.
* **Борт и номер полёта задаёт сервер** (`СЕРИЙНЫЙ-R<номер>`): агент не может начислить наработку другому борту.
  Повторная отправка журнала не начисляет часы дважды.
* Журнал проходит обычный импорт. Его видно в «Импорте журналов» (формат `drone`), его можно открыть и при
  необходимости откатить.

## 6. Безопасность полёта

* **Настройте failsafe PX4** в QGroundControl → *Safety* (раздел Skyris «Настройка Failsafe»):
  - потеря пульта — Land или RTL;
  - низкий заряд;
  - геозона;
  - `COM_DISARM_LAND` > 0 — моторы выключаются после посадки, по этому агент определяет конец полёта;
  - для `offboard` — реакция на потерю OFFBOARD (`COM_OBL_RC_ACT`).
* **Первые полёты** — на малой высоте, в открытом месте, с пилотом на пульте в режиме Position.
* **Пределы задаются в двух местах**, действует более строгое:
  - на сервере — `TBO_DRONE_MAX_ALT_M` (120 м), `TBO_DRONE_MAX_DIST_M` (2000 м), `TBO_DRONE_MAX_HOME_OFFSET_M` (50 м),
    `TBO_DRONE_MIN_BATTERY_PCT` (50 %);
  - на борту — `[limits]` в `agent.conf`.
* Полёты выполняются по правилам использования воздушного пространства и в пределах прямой видимости.
  Ответственность за полёт — на эксплуатанте и пилоте.

## 7. Защита связи

* **Токен устройства:**
  - 256 бит; на сервере хранится только хеш SHA-256, на борту — файл с правами 600;
  - агент отказывается работать, если файл токена доступен другим пользователям;
  - неверные токены ограничиваются по адресу.
* **API разделены.** Агент видит только `/api/agent/*` и только свой борт. Сессия пользователя не открывает API
  агента, токен устройства — API пользователя. Отключённое администратором подключение получает отказ.
* **Права:**
  - смотреть — любая роль;
  - командовать полётом — инженер и администратор;
  - подключать борты и выпускать токены — администратор.
  - Все команды записываются в журнал аудита: `drone_prepare`, `drone_start`, `drone_rtl` и т. д.
* **HTTPS рекомендуется:** без него токен и команды идут по Wi-Fi открытым текстом. Сервер с Caddy `tls internal`:
  скопируйте корневой сертификат на борт и укажите `ca_file` в `agent.conf`.
* **Агент не принимает перенаправления и не использует прокси из окружения**, поэтому токен не уйдёт на другой адрес.
* **Служба `tbo-agent` ограничена в systemd:** `NoNewPrivileges`, `ProtectSystem=full`, `ProtectHome=read-only`,
  запись только в `/var/lib/tbo-agent`.

## 8. Проверка без дрона

* **Симулятор агента.** Тот же агент, вместо ROS — модель полёта с ускорением времени:

  ```bash
  cd agent && python3 -m tbo_agent --config agent.conf --sim --sim-speed 10
  ```

  Для проверки анализа датчиков есть `--sim-fault collision@2` — удар у точки 2.
* **Симулятор Technic (Gazebo, SITL PX4).** Агент запускается так же, как на борту, с исполнителем `mission` или `offboard`.
* **Автотесты:**
  - `agent/agent_tests` — агент на модели PX4/MAVROS/simple_offboard и на симуляторе; проходят и под Python 3.8, как на борту;
  - `tests/test_drones.py` — настоящий сервер и настоящий агент по HTTP.

## 9. Неполадки

| Признак | Что проверить |
|---|---|
| Борт «Нет связи» | Питание и Wi-Fi борта; `systemctl status tbo-agent`; адрес сервера в `agent.conf` (с борта: `curl АДРЕС/health`) |
| В журнале агента «Неверный токен устройства» | Токен перевыпущен или подключение удалено — `sudo ./install.sh --token` |
| «Подключение отключено администратором» | «Борты на связи» → «Включить» |
| Проверка «GPS» или «Точка дом» не пройдена | Борт на открытом месте, дождитесь фиксации (QGroundControl: 3D Fix, спутники) |
| «Борт в точке взлёта миссии» не пройдена | Поставьте борт в точку взлёта миссии или поправьте точку взлёта в редакторе миссии |
| «нет сервиса /mavros/mission/push» | Включите плагин `waypoint` в mavros.launch Technic или задайте `executor = offboard` |
| Старт: «моторы не включились (PX4: …)» | Текст причины от PX4 — Preflight Fail, калибровки, предохранитель. Исправьте и нажмите «Старт» снова, борт остаётся готовым |
| Журнал «будет передан при появлении связи» | Связь восстановится — журнал уйдёт сам; на борту: `/var/lib/tbo-agent/outbox` |

## 10. Ограничения прототипа

* Агент проверен:
  - на модели PX4/MAVROS/simple_offboard;
  - на собственном симуляторе;
  - на Python 3.8, как в ROS Noetic.

  Полёты на реальном Technic 6S и в симуляторе Gazebo **не выполнялись**. Перед эксплуатацией нужны наземные
  проверки и пробные полёты.
* Журнал PX4 (`.ulg`) остаётся на SD-карте контроллера (QGroundControl → Analyze → Log Download). tbo-tracker
  учитывает журнал агента: трек, акселерометр, события.
* Один сервер — один процесс: команды бортам упорядочиваются в памяти процесса, как и остальная логика.
