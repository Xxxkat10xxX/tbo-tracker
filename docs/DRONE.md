# Полёт на реальном борту: Skyris Technic 6S (Orange Pi 5 Pro + PX4)

tbo-tracker отправляет миссию на дрон, запускает её по кнопке оператора, показывает полёт на карте и после
посадки сам импортирует журнал полёта. Наработка и циклы начисляются борту и установленным узлам, удары
по акселерометру попадают в мониторинг падений и столкновений, срабатывают напоминания ТО.

```
 tbo-tracker (сервер, Raspberry Pi / Docker)            дрон Skyris Technic 6S
 ┌───────────────────────────────┐   Wi-Fi    ┌───────────────────────────────────────────┐
 │ миссии · журнал · ТО           │◄──────────►│ Orange Pi 5 Pro: служба tbo-agent         │
 │ /api/drones (оператор)        │  HTTPS     │   ↕ ROS Noetic: MAVROS, simple_offboard    │
 │ /api/agent  (токен устройства)│            │ PX4 (полётный контроллер) ◄── пульт пилота │
 └───────────────────────────────┘            └───────────────────────────────────────────┘
```

* **Агент `tbo-agent`** (каталог `agent/`) работает на бортовом компьютере. Он сам обращается к серверу, поэтому
  на дроне не нужно открывать входящие порты. Агенту нужны только Python 3.8+ и ROS-пакеты, которые уже есть в образе Technic.
* **Связь:**
  - сервер узнаёт агента по **токену устройства**;
  - команды агент получает долгим опросом и доставляет на борт за секунду;
  - состояние и телеметрию агент присылает каждые 1–5 с.
* **Полётом управляет PX4.** Агент загружает план в контроллер, включает режим и следит за полётом.
  **Пульт пилота главнее**: переключение режима на пульте забирает управление (штатная функция PX4).

## 1. Что нужно

* Дрон с образом Technic для Orange Pi 5 Pro:
  - ROS Noetic, служба `technic`;
  - подключение к PX4 по UART или USB — `rostopic echo -n1 /mavros/state` показывает `connected: True`;
  - для **локальных миссий** (в помещении) — заводская навигация Technic: Optical Flow с дальномером VL53L1X или ArUco;
  - для **миссий по GPS** — модуль GPS с компасом (разъёмы GPS и I2C полётного контроллера), калибровка компаса
    и GPS в навигации PX4 (раздел 4а);
  - настроенные failsafe (раздел 6).
* Сервер tbo-tracker и Wi-Fi, общий с дроном. Рекомендуется общий роутер: инструкция Skyris «Подключение к Wi-Fi
  сети», способ 1. Можно и так: сервер подключается к точке доступа дрона `technic-xxxx`, тогда адрес сервера будет
  в сети 10.42.0.x. Но в этом режиме одновременно работает только один дрон.
* В карточке борта в tbo-tracker — статус «В эксплуатации», обязательные узлы установлены, просроченных работ ТО нет.
  Иначе сервер не допустит борт к полёту.

## 1а. Развёртывание одной командой (сервер Raspberry Pi + борт Orange Pi)

Сценарий `deploy/field/deploy.sh` запускается **с компьютера в той же сети, что и обе платы** (Linux, macOS или
Windows WSL; нужны `ssh` и `tar`). Из облака или другой сети платы недоступны.

```bash
./deploy/field/deploy.sh --server user@192.168.50.10 --drone orangepi@10.255.37.62
```

Что делает сценарий:

1. **Сервер:**
   - копирует исходники в `~/tbo-tracker` и запускает `deploy/raspberry-pi/install.sh` — служба, база, порт 80;
   - при первой установке установщик предлагает создать администратора, пароль вводится скрыто;
   - подключает борт командой `tbo-ctl drone add`: создаёт тип «Skyris Technic 6S» и борт с номером, равным
     имени хоста Orange Pi (`technic-xxxx`), и выпускает токен устройства.
2. **Борт:**
   - проверяет образ Technic: ROS Noetic, `technic_ws`, служба `technic`, не запущен ли `technic-show`;
   - проверяет **связь борта с сервером**: если сервер недоступен с борта, останавливается и объясняет причину;
   - копирует агент в `~/tbo-agent` и ставит его: `install.sh --server … --token-file …`.
3. **Токен** проходит с сервера на борт через ваш компьютер: в памяти и во временных файлах с правами 600, которые
   сразу удаляются. На экран токен не выводится.
4. **Пароли** вводятся только в запросах `ssh` и `sudo`: сценарий их не видит и не хранит. Соединение с каждой платой
   одно на весь запуск, поэтому пароль каждой платы спрашивается один раз.
5. **Ошибка на любом шаге** останавливает сценарий с объяснением. Временные файлы с токеном удаляются и при ошибке.

Параметры:
- `--https` — сайт с HTTPS (Caddy): борт получает корневой сертификат и обращается к `https://<адрес сервера>`;
- `--port N` — сайт без HTTPS на другом порту;
- `--demo` — демо-данные;
- `--serial`, `--name` — номер и название борта в tbo-tracker;
- `--drone-only` — переустановить только агент: сначала проверяет связь борта с сервером, затем выпускает новый
  токен (прежний перестаёт действовать);
- `--server-only` — только сервер.

**Windows (Git Bash).** ssh из Git для Windows не держит общее соединение, поэтому сценарий открывает отдельное
соединение на каждый шаг, и пароль платы спрашивается несколько раз. Чтобы паролей не было вовсе, один раз
настройте вход по ключу (в Git Bash):

```bash
ssh-keygen -t ed25519
```

```bash
cat ~/.ssh/id_ed25519.pub | ssh user@192.168.50.10 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

```bash
cat ~/.ssh/id_ed25519.pub | ssh orangepi@10.255.37.62 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

Запускайте сценарий из открытого окна Git Bash (`cd tbo-tracker`, затем команду), а не двойным щелчком: так окно
не закроется и сообщения останутся на экране. Если на Linux или macOS общее соединение не работает, задайте
`TBO_SSH_MUX=0`.

**Сервер без интернета.** Если Raspberry Pi не выходит в интернет (ошибка pip «Temporary failure in name
resolution»), сценарий сам скачивает пакеты Python на ваш компьютер (нужен интернет на компьютере и `curl`), сверяет
их SHA-256 и везёт на Pi. Принудительно — `TBO_OFFLINE=1`. Системные пакеты (`python3-venv` и др.) на Raspberry Pi OS
обычно уже стоят; если нет — подключите Pi к интернету на время первой установки. Борту интернет не нужен.

**Сеть.** Сервер и борт должны «видеть» друг друга: борт открывает адрес сервера (`http://192.168.50.10`).
Если они в разных подсетях (например, 192.168.50.x и 10.255.37.x) без маршрутизации между ними, подключите дрон
к той же сети, что и сервер (Skyris: «Подключение к Wi-Fi сети»), или настройте маршрут. Проверка с борта:

```bash
python3 -c "import urllib.request; print(urllib.request.urlopen('http://192.168.50.10/health').read())"
```

**После установки смените пароли по умолчанию.** Пароль `orangepi` образа Technic известен всем. Лучше входить
по SSH-ключам (Skyris: «Подключение к Orange Pi с использованием SSH-ключей»).

## 2. Подключение борта (один раз)

1. **Выпустить токен.** Администратор: «Борты на связи» → **«+ Подключить борт»** → выбрать борт → «Выпустить токен».
   - Токен показывается **один раз**. В базе хранится только его хеш.
   - Одному борту соответствует одно подключение.
2. **Скачать агент.** Там же кнопка **«⇩ Агент для борта»** (`tbo-agent.tar.gz`). Скопируйте архив на борт:

   ```bash
   scp tbo-agent.tar.gz orangepi@АДРЕС_БОРТА:~
   ```

3. **Установить агент на борту** (`ssh orangepi@АДРЕС_БОРТА`):

   ```bash
   tar xzf tbo-agent.tar.gz && cd tbo-agent && sudo ./install.sh
   ```

   Установщик:
   - спросит адрес сервера, например `https://tbo.local` или `http://192.168.1.10:8000`;
   - спросит токен (**ввод скрыт**, токен сохраняется в `/etc/tbo-agent/token` с правами 600);
   - проверит связь с сервером и запустит службу `tbo-agent` (после `technic`).
4. **Проверить.** `journalctl -u tbo-agent -f` → «подключён к …: борт …». В «Бортах на связи» борт станет **«На связи»**:
   видны батарея, GPS, режим, версия агента и исполнитель.

Заменить токен (например, при утечке): «Новый токен» в tbo-tracker, затем `sudo ./install.sh --token` на борту.

## 3. Полёт (оператор, роль «Инженер» или «Администратор»)

1. **Открыть миссию.** «Миссии» → миссия с назначенным бортом. В правой колонке — панель **«Полёт на борту»**.
2. **«⇪ Отправить план на борт».** Миссия сохраняется. Сервер проверяет:
   - допуск борта по ТО и комплектности;
   - пределы реального полёта: высота ≤ `TBO_DRONE_MAX_ALT_M`, удаление ≤ `TBO_DRONE_MAX_DIST_M`.

   Затем агент на борту:
   - проверяет целостность плана (хеш) и то, что план для **этого** борта;
   - проверяет собственные пределы борта;
   - проверяет связь с контроллером, что моторы выключены, GPS (3D, спутников ≥ `min_sats`) и точку «дом»;
   - проверяет, что борт стоит **в точке взлёта миссии** (допуск `max_home_offset_m`) и заряд батареи достаточен;
   - загружает план в PX4 и **сверяет его обратным чтением**.

   Результат каждой проверки виден в панели. Если всё пройдено — **«Готов к старту»**.
3. **«▶ Старт».** Нужно подтвердить три пункта: зона взлёта свободна, пилот с пультом на месте, полёт разрешён.
   - Команда «Старт» живёт **15 секунд**: старая команда после обрыва связи не выполнится.
   - Перед стартом борт повторяет проверки и ещё раз сверяет план в контроллере. Если его поменяли, например
     из QGroundControl, старт отменяется.
4. **Полёт.**
   - На карте миссии видны положение борта и пройденный трек. В панели — режим PX4, высота, скорость, батарея,
     GPS, точка маршрута, сообщения PX4.
   - **«⌂ Вернуть домой»** (AUTO.RTL) срабатывает сразу. Если связь пропала, команда доставится при восстановлении,
     в течение 2 минут.
   - **«⤓ Посадить на месте»** (AUTO.LAND) — с подтверждением.
   - **Связь пропала и не вернулась.** Если борт молчит в полёте дольше 10 минут, появляется кнопка
     «Закрыть полёт без журнала»: полёт помечается «не выполнен», и борт можно снова готовить к полётам.
     Найдите и осмотрите борт. Если агент позже передаст журнал (он хранится на борту), наработка будет учтена.
5. **После посадки** агент передаёт журнал, сервер импортирует его автоматически. В панели и в «Истории
   выполнения» появляется итог:
   - «Выполнена» или «Прервана»: возврат или посадка по команде, перехват пилотом;
   - длительность, путь, высота, номер импорта, начисленная наработка, события датчиков.
6. **Видео с борта** — карточка под картой маршрута, для любой роли. Поток берётся с web_video_server образа
   Technic (порт 8080) **через сервер**: браузер к борту не обращается (страница разрешает картинки только
   с этого сайта, адрес борта в сети меняется). Сервер подключается к адресу, с которого агент последний раз
   выходил на связь, и только к перечисленным потокам:
   - «Камера» — 640×480, около 30 кадров/с, ~2 Мбит/с;
   - «Камера (меньше кадров и трафика)» — тема `image_raw_throttled`, ~5 кадров/с;
   - «ArUco — распознанные маркеры» и «Оптический поток (отладка)».

   Видео включается кнопкой и останавливается при потере связи с бортом, при скрытой вкладке и через
   `TBO_DRONE_VIDEO_MAX_MIN` минут. Одновременных просмотров — не больше `TBO_DRONE_VIDEO_MAX`.
   Перед показом сервер ждёт первый кадр. Если камера не публикует изображение, будет ошибка
   «Камера борта не даёт кадров». Для потоковой отправки изображения на борту нужен пакет
   `ros-noetic-compressed-image-transport`: без него узлы сжатия видео образа Technic перезапускаются
   непрерывно и перегружают бортовой компьютер (раздел 9).

## 3а. Локальная миссия (в помещении, без GPS)

Заводская настройка Technic 6S — полёты в помещении:
- навигация по Optical Flow (камера вниз и дальномер VL53L1X до 4 м) или по ArUco-маркерам;
- GPS и магнитометр в PX4 выключены (`EKF2_GPS_CTRL = 0`, `EKF2_MAG_TYPE = None`).

Для такого дрона в редакторе миссии выберите **«Навигация: Локальная»**.

* **Точки** задаются в метрах от точки взлёта: «Вперёд» и «Вправо». **Верх карты — направление носа дрона в момент
  взлёта.** Поставьте дрон в точку взлёта носом туда, куда маршрут ведёт «вверх».
* **Пределы:**
  - высота до 3 м (`TBO_DRONE_LOCAL_MAX_ALT_M`; дальномер меряет до 4 м);
  - удаление до 20 м (`TBO_DRONE_LOCAL_MAX_DIST_M`);
  - скорость до 2 м/с — Optical Flow ограничивает горизонтальную скорость.
* **Как летит борт** — как в примерах Skyris:
  1. `navigate(z, frame_id='body', auto_arm=True)` — взлёт;
  2. `navigate(x, y, z, frame_id='map')` по точкам — координаты пересчитываются от точки взлёта с учётом курса;
  3. возврат к точке взлёта и `land()`.
* **Когда точка считается достигнутой.** Борт сравнивает своё положение в кадре `map` с целью, которую вычислил
  сам: кадр `navigate_target` после новой команды может ещё показывать прежнюю цель. Точка достигнута, если борт
  в допуске `local_tolerance_m` (0,25 м) три отсчёта подряд или держится не дальше двойного допуска 3 с —
  оптический поток «плавает», и иначе борт висел бы у близкой точки до тайм-аута. Точка прямо над точкой взлёта
  допустима (например, подняться и удержаться), маршрут после неё выполняется полностью.
* **Редактор маршрута:** щелчок по карте — новая точка, перетаскивание — перенос; щелчок по точке — выбрать
  (удалить — кнопкой «✕ Точка» или клавишей Delete), правый щелчок — удалить; «Очистить маршрут» — удалить все.
  Щелчок по значку точки взлёта «Т» точку не добавляет.
* **«Вернуть домой»** — полёт к точке взлёта и посадка программой на борту: AUTO.RTL без GPS недоступен.
  **«Посадить»** — `land()` на месте.
* **Проверки на борту:** связь с контроллером, моторы, **локальная позиция** (Optical Flow / ArUco), simple_offboard,
  заряд. GPS не требуется.
* В QGroundControl локальная миссия не экспортируется: в файлах `.plan` есть только GPS-координаты.

## 4. Исполнители плана (`/etc/tbo-agent/agent.conf` → `[vehicle] executor`)

| Исполнитель | Как летит | Когда выбирать |
|---|---|---|
| `mission` | План загружается в PX4 как миссия (`mavros/mission/push`): взлёт, скорость, точки с удержанием, возврат домой или посадка. Старт — AUTO.MISSION и арминг, как «Start Mission» в QGroundControl | Рекомендуется для GPS-полётов: полёт ведёт сам PX4, он виден в QGroundControl и продолжается при сбое бортового компьютера |
| `offboard` | Программа на борту по образцу Technic (раздел «Программирование автономного полёта»): `navigate(z, frame_id='body', auto_arm=True)` → `navigate_global` по точкам → AUTO.RTL или `land` | Если плагин миссий MAVROS отключён, или нужен полёт средствами simple_offboard |
| `auto` (по умолчанию) | `mission`, если в MAVROS есть сервисы миссии, иначе `offboard` | — |

В Technic часть плагинов MAVROS отключена (`plugin_blacklist` в `/home/orangepi/technic_ws/src/technic/technic/launch/mavros.launch`).
Чтобы работал `mission`, уберите из этого списка `waypoint` и перезапустите `sudo systemctl restart technic`.
Какой исполнитель выбран, видно в «Бортах на связи».

**Перехват управления пилотом.**
- В режиме `offboard` при переключении режима на пульте программа на борту немедленно прекращает работу и больше
  не отправляет борту команд.
- При сбое программы в воздухе исполнитель `offboard` переводит борт в AUTO.RTL.

## 4а. Technic 6S: что важно знать (docs.skyris.ru/technic6S)

| Что | Как учтено в tbo-tracker |
|---|---|
| ПО борта — служба `technic`: ROS Noetic, MAVROS, simple_offboard; рабочее пространство `~/technic_ws` | Агент запускается после `technic` и подключает `/opt/ros/noetic` и `~/technic_ws/devel/setup.bash` |
| ROS-сеть образа работает по имени `<hostname>.local`: в примерах Skyris `ROS_HOSTNAME=$(hostname).local` | `run-agent.sh` задаёт `ROS_HOSTNAME` так же; изменить — в `/etc/tbo-agent/ros.env` |
| Заводские параметры PX4 Technic — для помещения: `EKF2_GPS_CTRL = 0`, барометр выключен, `SYS_HAS_MAG = 0` | Агент читает параметры через `mavros/param/get` и для миссии по GPS объясняет, что GPS выключен; для таких дронов — локальные миссии |
| GPS — дополнительный модуль с компасом: разъёмы GPS и I2C, калибровка компаса, включить GPS в EKF2 (`EKF2_AID_MASK` или `EKF2_GPS_CTRL` в PX4 ≥ 1.14) | Проверки GPS: фиксация, спутники, точка «дом»; проверка параметра GPS в навигации |
| Плагины MAVROS частично отключены (`plugin_blacklist` в `~/technic_ws/src/technic/technic/launch/mavros.launch`); `git checkout .` в `~/technic_ws/src/technic` откатывает правки | Исполнитель `auto`: без плагина миссий (`waypoint`) — программа на борту (OFFBOARD). После отката launch-файлов включите `waypoint` снова |
| Прервать автономный полёт пилотом — перевести режим на пульте из Position в Stab | Программа на борту при любом режиме, кроме OFFBOARD, немедленно останавливается и ничего не переключает |
| `technic-show.service` (Техник-шоу) — второй клиент управления дроном через MAVROS | Проверка «Нет другого клиента управления»: при запущенном `technic-show` подготовка не выполняется |
| Акселерометр приходит в MAVROS (`/mavros/imu/data`) из потока HIGHRES_IMU, который PX4 передаёт в режиме MAVLink Onboard (50 Гц); часть плагинов MAVROS в образе Technic отключена | Перед полётом агент проверяет, что поток есть и на земле ≈ 1 g; иначе предупреждение ⚠: падения и столкновения не будут обнаружены. Нули от MAVROS (поток не передаётся) не принимаются за невесомость |
| `COM_DISARM_LAND > 0` — моторы выключаются после посадки | Если параметр ≤ 0, борт предупреждает (⚠): полёт завершится через 10 с на земле |
| QGroundControl — TCP `10.42.0.1:5760` в режиме точки доступа | Можно наблюдать полёт в QGroundControl параллельно с tbo-tracker |
| Wi-Fi: ползунок AP/AUTO на SKYRIS SHIELD; общая сеть — через Technic Console или `nmcli` | Для нескольких дронов и сервера — общий роутер |
| Пользователь `orangepi`, пароль по умолчанию `orangepi` | Смените пароль, используйте SSH-ключи |

## 5. Журнал и учёт

* **Что пишет агент:**
  - трек — 1 раз в секунду;
  - акселерометр |a| — 25 Гц: в каждом интервале 40 мс сохраняется значение с наибольшим отклонением от 1 g, поэтому
    не теряются ни пики ударов, ни провалы невесомости. Время отсчёта — по метке сообщения MAVROS, а не по приходу.
    Пропуск потока заполняется нейтральным 1 g: повтор последнего значения дорисовал бы ложную невесомость или удар;
  - удар на земле до взлёта (например, опрокидывание при запуске): полёта нет, поэтому события на сервере нет,
    но в итоге попытки указано «удар N g на земле — осмотрите винты, лучи и подвес»;
  - смена режимов, сообщения PX4, заряд в начале и в конце, достигнутые точки.
* **Время полёта** привязано к часам сервера. У Orange Pi без интернета часы могут быть неверными, поэтому агент
  сверяется с сервером при каждом обмене.
* **Журнал не теряется.** Сначала он сохраняется на борту (`/var/lib/tbo-agent/outbox`), потом передаётся.
  При отсутствии связи передача повторяется каждые 30 с. После перезапуска агента в полёте наблюдение продолжается;
  если агент перезапустился уже после посадки, журнал восстанавливается по контрольной точке.
* **Борт и номер полёта задаёт сервер** (`СЕРИЙНЫЙ-R<номер>`): агент не может начислить наработку другому борту.
  Повторная отправка журнала не начисляет часы дважды.
* Журнал проходит обычный импорт. Его видно в «Импорте журналов» (формат `drone`), его можно открыть и при
  необходимости откатить.

## 6. Безопасность полёта

* **Настройте failsafe PX4** в QGroundControl → *Safety* (раздел Skyris «Настройка Failsafe»):
  - потеря пульта — Land или RTL;
  - низкий заряд;
  - геозона;
  - `COM_DISARM_LAND` > 0 — моторы выключаются после посадки, по этому агент определяет конец полёта;
  - для `offboard` — реакция на потерю OFFBOARD (`COM_OBL_RC_ACT`).
* **Первые полёты** — на малой высоте, в открытом месте, с пилотом на пульте в режиме Position.
* **Пределы задаются в двух местах**, действует более строгое:
  - на сервере — `TBO_DRONE_MAX_ALT_M` (120 м), `TBO_DRONE_MAX_DIST_M` (2000 м), `TBO_DRONE_MAX_HOME_OFFSET_M` (50 м),
    `TBO_DRONE_MIN_BATTERY_PCT` (50 %); для локальных миссий — `TBO_DRONE_LOCAL_MAX_ALT_M` (3 м),
    `TBO_DRONE_LOCAL_MAX_DIST_M` (20 м), скорость до 2 м/с;
  - на борту — `[limits]` в `agent.conf`, для локальных миссий — `local_max_alt_m`, `local_max_dist_m`,
    `local_max_speed_ms`.
* Полёты выполняются по правилам использования воздушного пространства и в пределах прямой видимости.
  Ответственность за полёт — на эксплуатанте и пилоте.

## 7. Защита связи

* **Токен устройства:**
  - 256 бит; на сервере хранится только хеш SHA-256, на борту — файл с правами 600;
  - агент отказывается работать, если файл токена доступен другим пользователям;
  - неверные токены ограничиваются по адресу.
* **API разделены.** Агент видит только `/api/agent/*` и только свой борт. Сессия пользователя не открывает API
  агента, токен устройства — API пользователя. Отключённое администратором подключение получает отказ.
* **Права:**
  - смотреть — любая роль;
  - командовать полётом — инженер и администратор;
  - подключать борты и выпускать токены — администратор.
  - Все команды записываются в журнал аудита: `drone_prepare`, `drone_start`, `drone_rtl` и т. д.
* **HTTPS рекомендуется:** без него токен и команды идут по Wi-Fi открытым текстом. Сервер с Caddy `tls internal`:
  скопируйте корневой сертификат на борт и укажите `ca_file` в `agent.conf`.
* **Агент не принимает перенаправления и не использует прокси из окружения**, поэтому токен не уйдёт на другой адрес.
* **Служба `tbo-agent` ограничена в systemd:** `NoNewPrivileges`, `ProtectSystem=full`, `ProtectHome=read-only`,
  запись только в `/var/lib/tbo-agent`.

## 8. Проверка без дрона

* **Симулятор агента.** Тот же агент, вместо ROS — модель полёта с ускорением времени:

  ```bash
  cd agent && python3 -m tbo_agent --config agent.conf --sim --sim-speed 10
  ```

  Для проверки анализа датчиков есть `--sim-fault collision@2` — удар у точки 2.
* **Симулятор Technic (Gazebo, SITL PX4).** Агент запускается так же, как на борту, с исполнителем `mission` или `offboard`.
* **Автотесты:**
  - `agent/agent_tests` — агент на модели PX4/MAVROS/simple_offboard и на симуляторе; проходят и под Python 3.8, как на борту;
  - `tests/test_drones.py` — настоящий сервер и настоящий агент по HTTP.

## 9. Неполадки

| Признак | Что проверить |
|---|---|
| Борт «Нет связи» | Питание и Wi-Fi борта; `systemctl status tbo-agent`; адрес сервера в `agent.conf` (с борта: `curl АДРЕС/health`) |
| В журнале агента «Неверный токен устройства» | Токен перевыпущен или подключение удалено — `sudo ./install.sh --token` |
| «Подключение отключено администратором» | «Борты на связи» → «Включить» |
| Проверка «GPS» или «Точка дом» не пройдена | Борт на открытом месте, дождитесь фиксации (QGroundControl: 3D Fix, спутники) |
| «Борт в точке взлёта миссии» не пройдена | Поставьте борт в точку взлёта миссии или поправьте точку взлёта в редакторе миссии |
| «нет сервиса /mavros/mission/push» | Включите плагин `waypoint` в mavros.launch Technic или задайте `executor = offboard` |
| Старт: «моторы не включились (PX4: …)» | Текст причины от PX4 — Preflight Fail, калибровки, предохранитель. Исправьте и нажмите «Старт» снова, борт остаётся готовым |
| Журнал «будет передан при появлении связи» | Связь восстановится — журнал уйдёт сам; на борту: `/var/lib/tbo-agent/outbox` |
| Дрон садится посреди маршрута; «телеметрия: нет ответа»; нагрузка бортового компьютера ~8 | Узлы `*_web_compress` перезапускаются непрерывно (в `~/.ros/log/latest/roslaunch-*.log` — тысячи «restarting os process», код −6): в образе нет `ros-noetic-compressed-image-transport` — `sudo apt-get install ros-noetic-compressed-image-transport`. Причину посадки агент пишет в `/var/lib/tbo-agent/ros/log/tbo_agent.log` («программа полёта прервана») |
| «Видео с борта»: «Нет связи с видеосервером» / «не даёт кадров» | На борту `curl -s localhost:8080/` — список тем web_video_server (служба `technic`); тема камеры публикуется (`rostopic hz /main_camera/image_raw`) |

## 10. Ограничения прототипа

* Агент проверен:
  - на модели PX4/MAVROS/simple_offboard, в том числе с заводскими параметрами Technic для помещения;
  - на локальных миссиях и проверках параметров PX4;
  - на собственном симуляторе;
  - на Python 3.8, как в ROS Noetic.
* Сценарий развёртывания проверен на стенде: два SSH-хоста, оба установщика, передача токена, проверка связи.

  Полёты на реальном Technic 6S и в симуляторе Gazebo **не выполнялись**. Перед эксплуатацией нужны наземные
  проверки и пробные полёты.
* Журнал PX4 (`.ulg`) остаётся на SD-карте контроллера (QGroundControl → Analyze → Log Download). tbo-tracker
  учитывает журнал агента: трек, акселерометр, события.
* Один сервер — один процесс: команды бортам упорядочиваются в памяти процесса, как и остальная логика.
