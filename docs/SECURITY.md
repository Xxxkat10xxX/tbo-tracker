# Безопасность tbo-tracker

Модель угроз — сервис в сети предприятия или в интернете за HTTPS. Пользователи — сотрудники с разными правами.

## Учётные записи и пароли

### Хранение и требования к паролям

* Паролей по умолчанию и паролей в конфигурации **нет**.
* Пароли хранятся только как хеш **Argon2id**: t=3, m=64 МиБ, p=2, соль 16 байт (RFC 9106). Параметры записаны в самом хеше. Если их усилить, хеш пересчитается при следующем входе.
* Требования к паролю:
  - длина 10–128 символов;
  - не из списка распространённых;
  - без имени пользователя;
  - не меньше 4 разных символов.

  Удобнее всего фраза из нескольких слов.

### Первый администратор

Его можно создать тремя способами:

- одноразовым кодом настройки (около 100 бит; печатается в журнал сервиса и в файл `setup-code.txt` с правами 600, после использования удаляется);
- командой `python -m app.admin create-user` (пароль вводится скрыто или передаётся через stdin, но не аргументом);
- из Docker secret `TBO_ADMIN_PASSWORD_FILE`.

### Роли

| Роль | Права |
|---|---|
| Администратор | пользователи, сервер, резервные копии, аудит, демо-сброс |
| Инженер | изменение данных |
| Наблюдатель | только чтение |

Защита администраторов:

- последнего активного администратора нельзя удалить, понизить или отключить;
- себя — тоже нельзя.

### Временные пароли и восстановление доступа

- Пароль, заданный администратором, можно пометить как временный. Пока его не сменят, доступны только смена пароля и выход.
- Забытый пароль сбрасывает администратор: в разделе «Пользователи» или командой `tbo-ctl user passwd` / `app.admin passwd`.

## Сессии

### Токен и cookie

* Токен — 256 бит из `secrets.token_urlsafe`. В базе хранится только **SHA-256** от него, поэтому утечка базы не даёт войти.
* Cookie:
  - `HttpOnly; SameSite=Strict; Path=/`;
  - при HTTPS — `__Host-tbo_session; Secure`.

### Срок жизни и завершение

* Выход происходит после 120 минут бездействия; предельный срок сессии — 12 часов (настраивается).
* При новом входе прежняя сессия этого браузера завершается.
* Все сессии пользователя завершаются, если:
  - сменён его пароль (кроме текущей сессии самого пользователя);
  - изменена роль;
  - учётная запись отключена или удалена.
* При восстановлении из резервной копии из системы выходят все пользователи.

## Защита от перебора

* После 5 неудачных входов учётная запись блокируется на 15 минут. При повторах срок удваивается, максимум до суток.
* С одного адреса — не больше 20 неудачных попыток за 15 минут.
* Несуществующие имена ведут себя так же, как существующие: одинаковый текст ошибки, фиктивная проверка хеша, такая же «блокировка». Перечислить пользователей не получится.
* Подбор текущего пароля в форме смены пароля: после 5 неудач сессия завершается.
* Одновременно выполняется не больше двух хеширований — защита памяти и процессора.

## Запросы

### Права и CSRF

* Доступ проверяется для каждого запроса: требуемая роль задаётся в одном месте (`app/security.py`). Тест `test_every_route_has_an_access_rule` проверяет, что правило есть у каждого метода API.
* Без входа доступны только:
  - оболочка интерфейса и статика;
  - `/health`;
  - `/api/auth/state`, `login`, `setup`.

  Фото (`/media`), документация API и все данные требуют входа.
* **CSRF:**
  - для изменяющих запросов нужен заголовок `X-CSRF-Token`, совпадающий с токеном сессии (сравнение за постоянное время);
  - дополнительно проверяется `Origin`;
  - для входа и настройки нужен заголовок `X-Requested-With`. С чужого сайта его не отправить без CORS, а CORS выключен.

### Ограничения размера и разбор файлов

* Размер запроса ограничен: 25 МБ, для резервных копий — 512 МБ. Потоковые тела без `Content-Length` отклоняются.
* Excel и PDF разбираются с ограничениями:
  - распакованный размер — 200 МБ;
  - число строк — 50 000;
  - число страниц — 300.
* Повреждённые файлы дают понятный отказ, а не ошибку сервера.

### Ошибки и проверка ввода

* Входные данные проверяются схемами. NaN и бесконечность в числах отклоняются.
* Ответы об ошибках не повторяют введённые значения и не содержат трассировок.

## Браузер

* Строгая **Content-Security-Policy**: `default-src 'self'; script-src 'self'; style-src 'self'; object-src 'none'; frame-ancestors 'none'; base-uri 'none'`.
  - Встроенных скриптов, стилей и обработчиков в разметке нет.
  - Динамические размеры (полосы, графики) задаются через CSSOM.
* Остальные заголовки:
  - `X-Frame-Options: DENY`;
  - `X-Content-Type-Options: nosniff`;
  - `Referrer-Policy: no-referrer`;
  - `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy: same-origin`;
  - `Permissions-Policy` (камера, микрофон и геолокация запрещены);
  - HSTS при HTTPS;
  - `Cache-Control: no-store` для API.
* Все данные выводятся через экранирование. Тест с XSS-подстановками в названия бортов, узлов, типов, регламентов, миссий и файлов проходит без срабатываний.
* Загружаемые фото проверяются по сигнатуре: принимаются только JPEG, PNG и WebP. SVG не принимается, потому что может содержать скрипт. Имена файлов случайные.

## Сервер

* **Docker:**
  - пользователь `uid 10001`;
  - `read_only` для корневой ФС;
  - `cap_drop: ALL`, `no-new-privileges`;
  - лимиты памяти и процессов;
  - база не публикуется наружу;
  - пароль БД — Docker secret.
* **Raspberry Pi** (служба systemd):
  - пользователь `tbo` без входа;
  - `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, `NoNewPrivileges`;
  - запись только в `/var/lib/tbo-tracker`;
  - `UMask=0077`;
  - порт 80 открывается через `CAP_NET_BIND_SERVICE`, без root.
* Файлы данных — 600, каталоги — 700. Резервные копии содержат хеши паролей, поэтому скачивать их может только администратор.
* Документация API (`/docs`) по умолчанию выключена, а включённая доступна только администратору. Заголовок `Server` не отправляется.
* Демо-режим по умолчанию выключен:
  - сброс базы и сценарии недоступны;
  - генератор журналов не пишет вымышленные полёты в рабочую базу.
* Заголовки `X-Forwarded-*` принимаются только от доверенных прокси (`TBO_TRUSTED_PROXIES`). Подменить IP-адрес в аудите нельзя.
* `TBO_ALLOWED_HOSTS` ограничивает имена сайта в заголовке `Host`: страница чужого домена, «перепривязанного» через DNS
  на адрес сервера (DNS rebinding), получает отказ 400. Рекомендуется при доступе по HTTP из локальной сети.
* Загруженные фото принимаются только как JPEG/PNG/WebP (по сигнатуре файла) и сохраняются под случайными именами;
  `/media` отдаёт только такие файлы. При восстановлении из копии посторонние файлы (HTML, скрипты, подкаталоги) пропускаются.

## Связь с бортами (агент tbo-agent)

* **Токен устройства:**
  - 256 бит, показывается один раз; на сервере хранится только SHA-256, на борту — файл с правами 600;
  - API агента (`/api/agent/*`) доступно только по нему, без cookie и CSRF;
  - неверные токены ограничиваются по IP-адресу.
* **Разделение доступа:**
  - агент управляет только своим бортом, номер полёта и борт в журнале задаёт сервер;
  - сессия пользователя не открывает API агента, токен устройства — API пользователя.
* **Команды полёта:**
  - отдают роли «Инженер» и «Администратор»; подключение бортов и токены — только администратор;
  - все команды пишутся в журнал аудита.
* **«Старт»:**
  - живёт 15 с;
  - выполняется только для плана, который борт подтвердил (хеш плана), при свежей телеметрии, пройденных проверках
    на борту и допуске по ТО;
  - перед стартом план в контроллере сверяется ещё раз.
* **Пределы высоты и удаления** проверяют сервер (`TBO_DRONE_*`) и агент (свои пределы), действует более строгое.
  Для локальных миссий в помещении пределы отдельные и меньше: 3 м высоты, 20 м удаления, 2 м/с.
* **Развёртывание одной командой** (`deploy/field/deploy.sh`):
  - пароли плат вводятся только в запросы `ssh` и `sudo` — сценарий их не получает, не хранит и не передаёт
    в аргументах;
  - токен борта идёт с сервера на борт через компьютер оператора: в памяти сценария и во временных файлах
    с правами 600, которые сразу удаляются; на экран и в журнал не выводится;
  - повторный запуск выпускает новый токен, прежний перестаёт действовать;
  - после установки смените пароль `orangepi` (заводской пароль образа Technic) и пароль сервера, лучше перейти
    на SSH-ключи.
* **Изменения по одному борту выполняются строго по очереди**, под блокировкой с перечитыванием из базы:
  запоздавшее состояние не затрёт итог полёта.
* **Агент:**
  - не использует прокси из окружения и не следует перенаправлениям;
  - служба systemd ограничена: `NoNewPrivileges`, `ProtectSystem=full`, `ProtectHome=read-only`.
  - Подробно — [DRONE.md](DRONE.md).

## Аудит

* В журнал аудита записываются:
  - входы и неудачные попытки, блокировки;
  - создание, изменение и удаление учётных записей, смена и сброс паролей;
  - **каждый изменяющий запрос к API** (кто, когда, с какого адреса, что, с каким результатом).

  Пароли и тела запросов в журнал не попадают.
* Запись идёт через очередь в отдельном потоке, поэтому запрос не ждёт записи в журнал.
* Срок хранения — 365 дней (`TBO_AUDIT_RETENTION_DAYS`).

## Что остаётся на стороне эксплуатанта

* **HTTPS** для любого доступа по сети. Без него пароли передаются открыто, и страница «Сервер» предупреждает об этом.
* **Обновления** ОС и образа: `docker compose pull/build`, `apt full-upgrade`.
* **Резервные копии** — регулярно скачивать на другой носитель.
* **Внешний доступ.** Не публикуйте сервис в интернет без HTTPS и надёжных паролей. Лучше давать доступ через VPN.
* **Секреты** (`secrets/`, токен Telegram на странице «Сервер») хранятся в каталоге данных с правами 600. Защищайте доступ к серверу.
