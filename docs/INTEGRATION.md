# Интеграция с БАС: интерфейсы и конфигурации подключения

Сводка всех способов, которыми tbo-tracker получает данные от беспилотников и передаёт им задания.
Подробности по каждому – в документах по ссылкам.

## 1. Интерфейсы

| Интерфейс | Направление | Формат и протокол | Ограничения | Документ |
|---|---|---|---|---|
| API бортового агента `/api/agent/*` | агент ⇄ сервер | HTTPS (HTTP в закрытой сети), JSON; токен устройства в заголовке; долгий опрос команд; журнал полёта POST `/api/agent/runs/{id}/log`, полёт вне tbo-tracker (QGroundControl, пульт) – POST `/api/agent/flights` | агент видит только свой борт; входящие порты на борту не нужны; токен 256 бит, на сервере только хеш | [DRONE.md](DRONE.md), разделы 2, 7 |
| MAVROS (ROS Noetic) | агент ⇄ PX4 | топики `/mavros/state`, `/mavros/imu/data`, `/mavros/global_position/*`; сервисы `mission/push`, `cmd/arming`, `set_mode`, `param/get`; simple_offboard `navigate`, `navigate_global`, `land` | нужен образ Technic или ROS Noetic с MAVROS; часть плагинов в Technic отключена (`plugin_blacklist`) | [DRONE.md](DRONE.md), разделы 4, 4а |
| MAVLink (pymavlink) | ПК ⇄ ArduPilot / PX4 | загрузка миссии `MISSION_ITEM_INT`, перевод в AUTO | скрипт-заготовка для стенда и SITL | `scripts/run_mission_mavlink.py` |
| Файлы миссий | сервер ⇄ наземная станция | QGroundControl `.plan` (JSON, ArduPilot и PX4), `.waypoints` (QGC WPL 110); команды 22 / 16 / 20 | локальные миссии (без GPS) в `.plan` не выгружаются | [LOG_FORMAT.md](LOG_FORMAT.md) |
| Журналы полётов | наземная станция → сервер | `tbo-flightlog/1.0`: JSON, CSV, Excel; акселерометр `imu`, события бортового ПО `events` | PX4 `.ulg` и ArduPilot `.bin` напрямую не читаются – этап 2 | [LOG_FORMAT.md](LOG_FORMAT.md) |
| Журналы движения узлов | учёт → сервер | Excel (`.xlsx`, шаблон в интерфейсе), текстовый PDF | PDF – только текстовый, без распознавания сканов | [LOG_FORMAT.md](LOG_FORMAT.md) |
| REST API для внешних систем | сервер ⇄ ERP, 1С, «Виртуальный гараж» | OpenAPI `/openapi.json`, JSON, сессия и CSRF | включается `TBO_API_DOCS=1`, доступ – администратор | [ARCHITECTURE.md](ARCHITECTURE.md) |
| Уведомления | сервер → люди и системы | Telegram Bot API, webhook (JSON POST) | – | [ARCHITECTURE.md](ARCHITECTURE.md) |

## 2. Две конфигурации подключения

| | Конфигурация 1. Борт на связи | Конфигурация 2. Через наземную станцию |
|---|---|---|
| Борт | Skyris Technic 6S: Orange Pi 5 Pro + PX4 | любой борт на ArduPilot или PX4 |
| Как задание попадает на борт | кнопка «Полёт на борту» → агент → MAVROS → PX4 (`mission` или `offboard`) | экспорт `.plan` / `.waypoints` → QGroundControl, или `run_mission_mavlink.py` |
| Как возвращаются данные | агент сам отправляет журнал после посадки: трек 1 Гц, акселерометр 25 Гц, режимы, события | журнал наземной станции или Excel загружается в «Импорт журналов» |
| Навигация | по GPS и локальная (в помещении: Optical Flow + VL53L1X или ArUco) | по GPS |
| Связь | Wi-Fi, сервер на Raspberry Pi или в облаке | не нужна во время полёта |
| Проверка | автотесты `agent/agent_tests`, `tests/test_drones.py`; симулятор агента `--sim`; около 50 реальных запусков на одном дроне | автотесты миссий и импорта; протокол испытаний, п. 1 и 5 |

Обе конфигурации приводят к одному результату: наработка начисляется борту и установленным узлам, акселерометр проверяется на падения и столкновения, срабатывают напоминания ТО.

## 3. Конфигурационные файлы

Параметры подключения меняются без правки кода и без изменений в полётном контроллере.

| Файл | Где | Что задаёт |
|---|---|---|
| `/etc/tbo-agent/agent.conf` (образец `agent/tbo-agent.conf.example`) | борт | адрес сервера, сертификат, исполнитель `auto` / `mission` / `offboard`, пределы высоты, удаления, заряда и спутников |
| `/etc/tbo-agent/token` | борт | токен устройства, права 600 |
| `/etc/tbo-agent/ros.env` | борт | окружение ROS, если нужно не по умолчанию (по умолчанию `ROS_MASTER_URI=http://127.0.0.1:11311`, `ROS_IP=127.0.0.1`) |
| `agent/tbo-agent.service` | борт | служба systemd с ограничениями прав |
| `.env` (образец `.env.example`) | сервер | база данных, адрес сайта, пределы полётов `TBO_DRONE_*`, каналы уведомлений |
| `deploy/field/deploy.sh` | компьютер в сети | установка сервера и агента одной командой |

## 4. Обработка отказов

| Отказ | Что происходит |
|---|---|
| Пропала связь борта с сервером | журнал сохраняется на борту (`/var/lib/tbo-agent/outbox`) и передаётся каждые 30 с до успеха |
| Агент перезапустился в полёте | наблюдение продолжается; после посадки журнал восстанавливается по контрольной точке |
| Моторы не включились при старте | причина от PX4 показывается оператору; борт возвращается в «Готов к старту» |
| Пилот переключил режим на пульте | программа на борту немедленно прекращает отправку команд, управление у пилота |
| Повторная отправка или загрузка журнала | часы не начисляются дважды: хеш файла, номер полёта, пересечение по времени |
| Нет потока акселерометра | предупреждение перед полётом: падения не будут обнаружены |
| Строки журнала с ошибками | отклоняются с причиной, корректные строки загружаются |

## 5. Ограничения

- Прямое чтение `.ulg` (PX4) и `.bin` (ArduPilot) – этап 2. Сейчас данные приходят от агента или через `tbo-flightlog`.
- Конфигурация 1 рассчитана на образ Technic (ROS Noetic, MAVROS). Для других бортов на PX4 нужен такой же стек ROS.
- Один сервер – один процесс: команды бортам упорядочиваются в памяти процесса.
