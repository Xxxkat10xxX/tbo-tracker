# Формат журналов эксплуатации `tbo-flightlog/1.0`

Поддерживаются JSON, CSV, Excel (`.xlsx`) и текстовый PDF. Формат определяется по содержимому:
`PK` – Excel, `%PDF-` – PDF, первый значимый символ `{` или `[` – JSON, иначе CSV.
Кодировка текстовых форматов – UTF-8 (допускается cp1251 для CSV из Excel).
Excel и PDF могут содержать не только полёты, но и **журнал движения узлов** (установка, снятие, перестановка) –
см. раздел [«Excel и PDF»](#excel-и-pdf).

Единица учёта – **полёт**: взлёт → посадка.

* часы наработки = `end − start`;
* циклы = поле `cycles` (взлёт-посадка; по умолчанию 1, «тач-энд-гоу» можно указать 2 и т. д.).

Все даты – ISO-8601. Без часового пояса трактуются как UTC; рекомендуется явный `Z` или смещение (`+03:00`).

## JSON

```json
{
  "format": "tbo-flightlog/1.0",
  "log_id": "TBT-M4-001-20261106",
  "aircraft_serial": "TBT-M4-001",
  "source": "Наземная станция управления (демо)",
  "flights": [
    {
      "flight_id": "TBT-M4-001-20261106-01",
      "start": "2026-11-06T06:00:00Z",
      "end": "2026-11-06T06:24:00Z",
      "cycles": 1,
      "mission": "Мониторинг ЛЭП",
      "pilot": "Петрова М."
    }
  ]
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `format` | нет | Идентификатор формата; если указан – должен начинаться с `tbo-flightlog/` |
| `aircraft_serial` | да* | Серийный номер борта для всех полётов файла |
| `flights[].aircraft_serial` | да* | Можно указать в каждом полёте (многобортовой журнал) |
| `flights[].flight_id` | рекомендуется | Уникальный ID полёта в пределах борта. Если нет – вычисляется из борта и времени |
| `flights[].start`, `end` | да | Время взлёта и посадки |
| `flights[].cycles` | нет | Число циклов, по умолчанию 1 |
| `mission`, `pilot` | нет | Справочная информация |
| `imu` | нет | Выборка акселерометра для мониторинга падений и столкновений (см. ниже) |
| `events` | нет | Готовые события бортового ПО: `[{"type": "fall"\|"collision", "t_s": 312.5, "peak_g": 6.1}]` |
| `falls`, `collisions` | нет | Счётчики падений / столкновений за полёт (если бортовое ПО их считает само) |

\* серийный номер нужен на уровне файла или полёта. Допускается и «голый» массив полётов.

## CSV

Одна строка – один полёт. Разделитель `,` или `;` (определяется автоматически). Строки, начинающиеся с `#`, – комментарии.

```csv
# tbo-flightlog/1.0 CSV
aircraft_serial,flight_id,start_utc,end_utc,cycles,mission,pilot
TBT-M4-003,TBT-M4-003-20261106-01,2026-11-06T07:00:00Z,2026-11-06T07:45:00Z,1,Мониторинг ЛЭП,Петрова М.
```

Обязательные колонки: `aircraft_serial`, `start_utc` (или `start`), `end_utc` (или `end`).
Необязательные: `flight_id`, `cycles`, `mission`, `pilot`, `falls`, `collisions`.
Русские заголовки тоже распознаются: «Борт», «Взлёт», «Посадка», «Циклы», «Задание», «Оператор», «Падения», «Столкновения».

## Датчики: падения и столкновения

Полёт JSON может содержать выборку модуля абсолютной перегрузки акселерометра (в g):

```json
"imu": {"rate_hz": 50, "t0_s": 330, "accel_g": [1.0, 1.02, 0.98, 0.12, 0.08, 0.1, 7.6, 2.1, 1.0]}
```

`t0_s` – смещение начала выборки от взлёта (выборка может покрывать только окно вокруг события).
`rate_hz` – частота выборки, 1–10 000 Гц (по умолчанию 50). Отсчёт – модуль `|a|` или тройка `[ax, ay, az]` в g;
пары и векторы другой длины не принимаются. Отсчёт без значения (`null`, `NaN`, `Infinity`) считается пропуском:
он не создаёт и не продлевает событие, а в описании события указано число таких отсчётов.

Акселерометр измеряет удельную силу: в висении `|a| ≈ 1 g`, в свободном падении `≈ 0`. Детектор (`app/services/sensors.py`):

* **падение** – `|a| < 0,35 g` не менее 0,2 с при любой частоте выборки (свободное падение), затем удар `≥ 3 g`
  в пределах 1,5 с;
* **падение без записанного удара** – запись оборвалась в невесомости (питание или связь пропали при ударе).
  Подтверждающего удара нет, поэтому критерий строже – как у детектора свободного падения PX4: `|a| < 2 м/с²`
  (0,2 g) не менее 300 мс. Пик перегрузки у такого события не указан;
* **столкновение** – удар `≥ 4 g` без предшествующей невесомости;
* **посадка** – удар без невесомости в последние 8 с полёта (по `start`/`end`) и после его окончания – касание
  земли и выключение моторов, не столкновение, если он слабее 10 g (сильнее – удар о землю, столкновение).
  Падение при посадке (невесомость, затем удар) остаётся падением;
* срабатывания ближе 1 с (от конца одного удара до начала следующего) – одно событие: отскоки не считаются
  отдельными ударами. Если в группе есть падение, событие – падение;
* «невесомость» дольше 10 с – не падение, а неверные данные (с сопротивлением воздуха перегрузка падающего
  борта за 1–2 с возвращается к 1 g).

Одно физическое событие не считается дважды:

* событие из `events` ближе 2 с к найденному по акселерометру объединяется с ним – сохраняется наибольший пик,
  а если хотя бы один источник говорит «падение», событие – падение;
* счётчики `falls` / `collisions` – общее число событий своего вида за полёт; добавляются только недостающие
  до найденных по `imu` и `events`.

Части данных датчиков проверяются независимо: ошибка в `events` не отменяет анализ `imu`, и наоборот.

События сохраняются за полётом (откат импорта удаляет и их), увеличивают счётчики борта и запускают регламенты
с интервалом «падений/столкновений» – для борта и для узлов, стоявших на нём в момент удара.

## Excel и PDF

Файл читается как набор таблиц: листы Excel, таблицы на страницах PDF (для PDF без разметки таблиц –
колонки, разделённые `|` или двумя пробелами). Заголовки, повторённые на каждой странице, пропускаются.
Регистр и порядок колонок не важны.

**Журнал движения узлов** – таблица с колонкой «Операция»:

| Колонка (синонимы) | Обязательно | Значение |
|---|---|---|
| Дата («Дата и время») | да | `07.11.2026 09:30` или ISO-8601 |
| Операция («Действие») | да | установка / монтаж · снятие / демонтаж · перестановка / перенос |
| Узел («Серийный номер узла») | да | серийный номер узла |
| Борт («На борт», «Куда») | для установки и перестановки | имя («Борт 11») или серийный номер борта |
| Позиция («Место») | для установки и перестановки | посадочное место (`ESC4`, `FC`…), регистр не важен |
| С борта («Откуда») | нет | для снятия и перестановки: если указан и не совпадает с бортом, где числится узел, строка отклоняется. При снятии вместо него можно заполнить «Борт» |
| Состояние после снятия | нет | резерв / ремонт / списание (по умолчанию резерв); другое значение – ошибка строки |
| Основание, Исполнитель | нет | записываются в историю установок |

Строки применяются в хронологическом порядке теми же правилами, что и ручные операции (совместимость позиции,
занятость, статус узла, даты). Ошибочная строка отклоняется с причиной, остальные применяются.
Каждая применённая строка запоминается по ключу «дата + операция + узел + борт + позиция», поэтому повторная
загрузка того же журнала – в том числе его PDF-версии – ничего не задваивает.
Шаблон: `GET /api/templates/movements.xlsx` (ссылка в разделе «Импорт журналов»).

**Журнал полётов** – таблица с колонками «Взлёт» и «Посадка» (и «Борт», если в файле несколько бортов);
обрабатывается как CSV, включая колонки «Падения» / «Столкновения».

Ограничение: сканированный PDF без текстового слоя не распознаётся.

## Миссии автономного полёта

Миссии экспортируются и импортируются в форматах наземных станций:

* QGroundControl `.plan` (JSON, `fileType: "Plan"`, `firmwareType` 3 – ArduPilot, 12 – PX4);
* `.waypoints` – QGC WPL 110 (табуляция; строка 0 – домашняя точка).

Команды MAVLink: `22` NAV_TAKEOFF (высота взлёта миссии), `16` NAV_WAYPOINT (param1 – удержание, с;
param4 – курс в точке, ° от севера, `null` – не задан), `20` NAV_RETURN_TO_LAUNCH; кадр `3` (GLOBAL_RELATIVE_ALT –
высота относительно точки взлёта).
Курс точки при импорте читается только из `.plan` PX4: в `.plan` ArduPilot и в `.waypoints` param4 обычно равен 0
и означает «не задан». Режим «Курс дрона: по линии маршрута» в файлы не переносится – у PX4 нос к точке
направляет параметр `MPC_YAW_MODE` (так по умолчанию).
При импорте точки в кадре `0` (GLOBAL – высота над уровнем моря) пересчитываются от высоты «дома»
(`plannedHomePosition` в `.plan`, строка 0 в `.waypoints`); высота взлёта берётся из команды NAV_TAKEOFF.
Результат автономного полёта в симуляторе записывается как журнал `tbo-flightlog/1.0` с полем `imu` (трек хранится в истории выполнения миссии)
и проходит штатный импорт.

Примеры: [`examples/example_flightlog.json`](examples/example_flightlog.json), [`examples/example_flightlog.csv`](examples/example_flightlog.csv).
Даты в примерах фиксированные. Для сценариев проверки используйте журналы, которые генерируются при заполнении
демо-данных (раздел «Импорт журналов» или `data/demo_logs/`).

## Правила обработки

* Повтор файла (тот же SHA-256) – ничего не начисляется, импорт фиксируется со статусом «Повтор».
  Исключение – файл, в прошлый раз импортированный частично с отклонёнными строками: его можно загрузить снова
  после исправления данных (например, зарегистрировали борт или узел) – применятся только ранее отклонённые строки,
  уже учтённые полёты и операции отсекаются проверкой на уровне строк.
* Некорректные данные датчиков (`imu`, `events`, «Падения», «Столкновения») не отменяют учёт полёта: полёт
  засчитывается, в отчёте – предупреждение «данные датчиков не учтены» с причиной. Время события ограничивается
  интервалом полёта.
* Полёт с уже известным `(борт, flight_id)` или пересекающийся по времени с учтённым полётом борта – дубликат, пропускается.
* Строки с ошибками отклоняются с указанием причины, остальные импортируются.
* Наработка начисляется борту и каждому узлу, который по истории установок числился на борту **в момент взлёта**.

## Генератор журналов

Журналы в этом формате можно создать генератором – раздел «Генератор журналов» или командная строка:

```bash
python -m app.loggen --aircraft TBT-M4-001 --from 2026-11-01 --to 2026-11-05 --format csv -o log.csv
```

| Параметр CLI | Поле в интерфейсе | Значение |
|---|---|---|
| `--aircraft A B …` | Борта | серийные номера (несколько – многобортовой журнал) |
| `--from`, `--to` / `--days N` | С даты / По дату | период (по умолчанию – последние N дней) |
| `--format json\|csv` | Формат | |
| `--flights 1-4` | Полётов в день | диапазон |
| `--duration 15-45` | Длительность, мин | диапазон |
| `--probability 0.8` | Вероятность лётного дня | |
| `--no-ids` | Указывать flight_id | без ID – дедупликация по времени |
| `--duplicates N` | Добавить дублей | N уже учтённых полётов |
| `--errors` | Ошибочные строки | 4 заведомо ошибочные строки |
| `--seed N` | Seed | повторяемый результат |
| `--import` | кнопка «Импортировать» | сразу загрузить в базу |

## API

```
POST /api/imports              multipart: file, dry_run=true|false, imported_by
POST /api/imports/{id}/rollback
POST /api/log-generator         генерация (import_now=true – сразу импорт)
POST /api/flights               ручной полёт;  DELETE /api/flights/{id} – удалить ручной полёт
GET  /api/imports, /api/imports/{id}
GET  /api/templates/movements.xlsx   шаблон журнала движения узлов
GET  /api/missions/{id}/export?fmt=plan|waypoints&firmware=ardupilot|px4
POST /api/missions/import       multipart: file (.plan / .waypoints)
```
