# Полная проверка всех функций tbo-tracker

Пошаговый чек-лист: каждый раздел интерфейса, каждая кнопка и каждое правило защиты данных.
Формат пункта: **что сделать → что должно получиться**. Отмечайте `[x]` по ходу.

Время прохождения целиком – около 1,5–2 часов. Разделы независимы, но рекомендуется идти по порядку:
состояние демо-данных описано именно для такого порядка.

> **Перед началом:**
> 1. Запустите приложение (`run.bat` / `run.sh` – демо-режим) и откройте <http://localhost:8000>.
> 2. При первом запуске введите **код настройки** из консоли и создайте администратора.
> 3. Внизу меню нажмите **«↺ Сбросить демо-данные»** → «Сбросить». Учётные записи сохранятся.
>
> Сброс можно повторять в любой момент, если что-то пошло не так.

Обозначения демо-данных (сгенерированы случайно): борта `TBT-M4-001` («Борт 01»), `TBT-M4-002` («Борт 02»), `TBT-M4-003` («Борт 03»),
`TBT-VT2-011` («Борт 11»), `TBT-VT2-012` («Борт 12»). Узлы: полётные контроллеры `FC7-…`, ИНС `IMU3-…`,
регуляторы `ESC40-…`, вычислители `BVK2-…`.

  в том числе в карточке узла и в «Свои типы узлов».

- [ ] «Перестановка узлов»: карточки всех бортов с позициями, колонки «Резерв» и «Ремонт».
- [ ] Перетаскивание узла: совместимые позиции подсвечены, остальные затемнены; отпускание на несовместимой – ничего не происходит.
- [ ] На пустую позицию → «Перестановка» (с борта) или «Установка» (из резерва); на занятую → «Обмен» / «Замена».
- [ ] В «Резерв» / «Ремонт» → «Снятие» с нужным состоянием; узел из «Ремонта» не перетаскивается.
- [ ] Окно подтверждения: план шагов, дата, исполнитель, основание; «Выполнить» → таблица «было → стало», узел подсвечен.
- [ ] Дата операции в прошлом → наработка переставленных узлов изменилась (полёты переотнесены).
- [ ] Без мыши: щелчок по узлу, затем по позиции – то же самое.

## 21. Сервер (страница «Сервер», Raspberry Pi)

- [ ] «Сервер»: показатели (модель, температура, загрузка, ОЗУ, диск, питание), адреса для подключения, сведения о сервисе,
  время последней фоновой проверки (обновляется каждую минуту), предупреждения (на ПК их может не быть).
- [ ] «Уведомления вне браузера»: включите webhook на заведомо несуществующий адрес (`http://127.0.0.1:9/x`) → «Отправить
  тестовое сообщение» → понятная ошибка доставки; адрес без `http://` → ошибка сохранения. Токен Telegram после сохранения
  показывается маской, пустое поле не стирает сохранённый токен.
- [ ] Импортируйте `07…padenie.json` → через ≤ 1 мин в «ТО и уведомления» → «Журнал уведомлений сервера» новые записи
  с результатом доставки по каналам («только в интерфейсе», если каналы выключены).
- [ ] «Резервные копии»: «+ Создать копию» → строка в списке; «⇩» скачивает .zip; переименуйте борт → «Восстановить»
  → имя вернулось, в списке появилась копия «перед восстановлением»; «⇪ Загрузить .zip» принимает скачанный файл,
  произвольный файл – отклоняется; «✕» удаляет копию.
- [ ] Перестановка на доске и сценарии выполняются сервером: при ошибке одного из шагов обмена не применяется ни один.
- [ ] Вход и права – раздел 22.
- [ ] Командная строка: `python -m app.admin status`, `backup`, `backups`, `restore ИМЯ`. На Raspberry Pi – `sudo tbo-ctl status`,
  `password`, `port`, `restore`, `update` (docs/RASPBERRY_PI.md).

## 22. Вход, учётные записи и безопасность

- [ ] Первый запуск на пустой базе → в консоли «Одноразовый код настройки», в каталоге данных `setup-code.txt` (права 600).
  Сайт показывает «Первичная настройка». Неверный код → отказ. Верный код, слабый пароль (`password123`, короче 10 символов,
  содержащий имя) → понятная причина. Подходящий пароль → вход; `setup-code.txt` удалён; повторная настройка невозможна.
- [ ] Выход → экран входа; неверный пароль → «Неверное имя пользователя или пароль» (то же для несуществующего имени).
  5 неверных попыток подряд → «Слишком много неудачных попыток. Повторите через N мин.»; верный пароль во время блокировки
  не помогает; «Пользователи» → «Разблокировать» (или `tbo-ctl user unlock`) снимает блокировку.
- [ ] «Пользователи»: создать инженера и наблюдателя (кнопка «Сгенерировать», флажок «Временный»). Войти наблюдателем в другом
  браузере → меню без «Генератора» и админ-разделов, кнопки изменения дают «Недостаточно прав… только просмотр».
  Войти инженером с временным паролем → сразу «Смените временный пароль»; после смены – работа с данными, но без «Сервер»,
  «Пользователи», «Журнал аудита».
- [ ] Смена роли или отключение пользователя → его открытая сессия завершается (следующее действие – экран входа).
  Нельзя удалить, понизить или отключить себя и последнего администратора.
- [ ] «Сменить пароль» (внизу меню): неверный текущий → отказ; после смены – другие браузеры этого пользователя вышли.
- [ ] Бездействие дольше `TBO_SESSION_IDLE_MIN` → следующее действие показывает «Сессия завершена – войдите снова».
- [ ] «Журнал аудита»: входы, неудачные попытки, блокировки, действия с учётными записями, изменения данных
  (метод, адрес, пользователь, IP, код ответа); фильтры по пользователю и событию; пароли в журнале не встречаются.
- [ ] Инструменты разработчика → «Сеть»: у ответов `Content-Security-Policy` без `unsafe-inline`, `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`, у API – `Cache-Control: no-store`; cookie `tbo_session` – HttpOnly, SameSite=Strict
  (за HTTPS – `__Host-tbo_session`, Secure, плюс HSTS). Консоль без ошибок CSP.
- [ ] Запрос изменения без заголовка `X-CSRF-Token` (например `curl -X PATCH` с cookie) → 403; с чужим `Origin` → 403.
- [ ] Без входа: `/api/aircraft`, `/media/…` → 401; `/`, `/static/…`, `/health` → 200.
- [ ] Демо-режим выключен (`TBO_DEMO_MODE=0`): нет «Сценариев проверки» и «Сбросить демо-данные», `POST /api/demo/reset` → 404,
  генератор не записывает полёты в базу (только скачивание и проверка без записи).
- [ ] Восстановление из копии → все пользователи вышли; учётные записи – как в копии (если в копии нет администратора – текущие).
- [ ] Docker: `docker compose … up -d` → `healthy`; `docker compose exec app id` → uid 10001; запись в `/app` запрещена
  (read-only); `docker compose exec app env` – пароля БД нет, только `TBO_DATABASE_PASSWORD_FILE`.

## 23. Полёт на реальном борту ([DRONE.md](DRONE.md))

Без дрона – тот же агент с симулятором: `cd agent && python3 -m tbo_agent --config agent.conf --sim --sim-speed 10`
(в `agent.conf` – адрес сервера и путь к файлу токена с правами 600).

- [ ] **Подключение борта.** «Борты на связи» (администратор) → «+ Подключить борт» → токен показан один раз,
  с командами установки; «⇩ Агент для борта» скачивает `tbo-agent.tar.gz`.
- [ ] **Агент на связи.** После запуска агента борт «На связи»: батарея, GPS, режим, версия агента, исполнитель.
  Остановка агента → через 15 с «Нет связи».
- [ ] **Отправка плана.** Миссия → «Полёт на борту» → «⇪ Отправить план на борт» → список проверок
  (контроллер, моторы, GPS, дом, точка взлёта, заряд, план загружен) → «Готов к старту».
- [ ] **Отказы при подготовке:**
  - миссия с точкой выше 120 м или дальше 2 км → отказ с причиной;
  - борт «На обслуживании» или с просроченной работой → «не допущен к полёту».
- [ ] **Старт.**
  - «Старт» без трёх отметок окно не закрывает; с отметками – «Полёт по маршруту», борт и трек на карте.
  - Наблюдатель видит панель, но кнопок команд у него нет.
- [ ] **Прерывание.** «⌂ Вернуть домой» → «Возврат домой» → посадка → «Прервана: возврат домой по команде оператора».
- [ ] **Итог после посадки.** «Выполнена», импорт №…, начислена наработка. В «Истории выполнения» строка «Борт»;
  в «Импорте журналов» – импорт формата `drone`; полёт в карточке борта.
  - `--sim-fault collision@2` → в карточке борта «Датчики» – столкновение.
- [ ] **Журнал аудита:** `drone_link_created`, `drone_prepare`, `drone_start`, `drone_rtl`, `drone_flight_logged`.
- [ ] **Повторная отправка журнала** (перезапуск агента с файлом в `outbox`) → «уже учтён», наработка не удваивается.
- [ ] **Локальная миссия (в помещении, Technic 6S по умолчанию).**
  - Редактор миссии → «Навигация: Локальная» → столбцы «Вперёд, м / Вправо, м» вместо широты и долготы,
    на карте «Т» (точка взлёта) и «нос» вместо «С»; кнопки экспорта в QGroundControl скрыты.
  - Скорость больше 3 м/с → «Сохранить» отклоняет с причиной (Optical Flow).
  - Высота 4 м или скорость 2,5 м/с → миссия сохраняется (для симулятора), но «Отправить план на борт» отклоняет:
    «выше предела 3 м (TBO_DRONE_LOCAL_MAX_ALT_M)», «выше 2 м/с для локальной навигации»; точка дальше 20 м – тоже.
  - Значение «Вправо» точки меняется и сохраняется: после перезагрузки страницы то же число.
  - «Полёт на борту» → проверки без GPS: «Локальная позиция (Optical Flow / ArUco)» вместо «GPS» и «Дом».
  - Старт → возврат к точке взлёта на высоте последней точки, без набора 5 м → посадка → «Выполнена».
  - API: экспорт локальной миссии (`/api/missions/{id}/export?fmt=plan`) → 400 «не переносится в QGroundControl».
- [ ] **Проверки по параметрам PX4 (борт с ROS).**
  - Миссия по GPS на Technic с заводскими параметрами (`EKF2_GPS_CTRL = 0`) → проверка «GPS в навигации PX4» не
    пройдена, с подсказкой.
  - Запущен `technic-show` → «Нет другого клиента управления» не пройдена.
  - `COM_DISARM_LAND ≤ 0` → предупреждение, подготовка не блокируется.
- [ ] **Развёртывание одной командой** (с компьютера в сети плат):
  - `./deploy/field/deploy.sh --server user@<Pi> --drone orangepi@<Orange Pi>` → сервер установлен, борт с номером
    `technic-xxxx` в «Бортах на связи», статус «На связи»;
  - в выводе сценария нет токена (`tbo_…`), во временных файлах на компьютере и платах – тоже;
  - на борту `/etc/tbo-agent/token` с правами 600, владелец `orangepi`;
  - повторный запуск с `--drone-only` выпускает новый токен, агент снова на связи.
