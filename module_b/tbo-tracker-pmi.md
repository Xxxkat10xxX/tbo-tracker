Кейс 5 «Обслуживание БПЛА по фактической наработке» (ООО «СПУТНИК-РЕД», КБ «СОКОЛ»). Команда НИЯУ МИФИ, Москва.

| Техническое задание | [tbo-tracker-tz.md](tbo-tracker-tz.md): характеристики Х1–Х7, модули М1–М3, сквозной сценарий, конфигурации подключения, дополнительные функции Д1–Д6, стенды |

## 1. Общие положения

**Что проверяется.** Десять требований кейса (раздел 4), семь обязательных характеристик Х1–Х7 (раздел 3), три
функциональных модуля М1–М3 (раздел 5), сквозной сценарий работоспособности и отказоустойчивости (раздел 7),
дополнительные функции Д1–Д6 (раздел 8), юзабилити (раздел 9).

**Методы испытаний.**

| Метод | Что даёт | Где |
|---|---|---|
| Функциональный | автотесты сервера и бортового агента; проверка интерфейса по шагам карточек | разделы 4, 5, 10 |
| Измерительный | замер против независимого эталона (модель парка, эталонный набор журналов, синтетические записи датчиков) | Х4–Х7, раздел 10 |
| Лётный | полёты реального борта по маршруту с отчётом по каждому полёту | Х1–Х3, Х5, М3, раздел 6 |
| Отказоустойчивость | сквозной сценарий с отказом сервера во время полёта | раздел 7 |
| Юзабилити | операции инженера в интерфейсе без подсказок и документации | раздел 9 |

**Правила.**

- Для каждой проверки ниже указаны цель, стенд и исходные условия, показатель с единицей и порогом, порядок действий,
  критерий успеха и допустимое число попыток.
- Испытание засчитывается, если в одной из допустимых попыток выполнены все критерии. Неудачные попытки тоже
  записываются в отчёт с причиной.
- Пороги и условия после начала испытаний не меняются. Фактическая последовательность действий и исходные данные
  записываются в отчёт; любое отступление от методики — в раздел «Отступления от методики» отчёта.
- Во время контрольных сценариев (раздел 7, раздел 8) не допускается правка кода, файлов настроек и конструкции.

**Стенды** (ТЗ, раздел 7): 1 — лётный (Raspberry Pi 5, рабочий режим, реальный борт, зона 4 × 6 м с полем ArUco);
2 — демо (ноутбук, демо-режим, перед проверкой «↺ Сбросить демо-данные»); 3 — прогон программной части.

## 7. Сквозной сценарий работоспособности и отказоустойчивости

| | |
|---|---|
| Цель | подтвердить, что при отказе сервера во время полёта борт выполняет маршрут, журнал не теряется и после восстановления учитывается ровно один раз |
| Стенд и исходные условия | стенд 1; ТЗ, раздел 5; узел у порога ТО (раздел 2, п. 5); второй терминал с журналом агента `journalctl -u tbo-agent -f` |
| Показатель | конечный результат достигнут (да / нет); число попыток; некритические сбои и восстановление |
| Критерий успеха | все шаги выполнены в одной из 3 попыток без правки кода, настроек и конструкции |
| Попыток | 3 |
| Фиксация | непрерывное видео всего сценария с таймкодами шагов; отчёт полёта R N |

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | «▶ Старт» миссии из 5 точек | взлёт, полёт по маршруту |
| 2 | После достижения 2-й точки: на сервере `sudo tbo-ctl stop` | веб-интерфейс недоступен; в журнале агента — сервер недоступен; борт продолжает маршрут |
| 3 | Посадка | посадка в точке взлёта; журнал полёта сохранён на борту в очереди (`/var/lib/tbo-agent/outbox`) |
| 4 | `sudo tbo-ctl start` | сервер работает; в «Борты на связи» борт «На связи» не позже 30 с |
| 5 | Ожидание без действий оператора | журнал доставлен не позже 60 с; полёт R N «выполнена»; наработка начислена один раз |
| 6 | «ТО и уведомления» | работа подготовленного узла сменила статус; уведомление |
| 7 | «⇩ журнал» полёта R N → «Импорт журналов» | «Повтор — не начислено», 0 ч |

Допустимые способы восстановления: повтор «Старта» при отказе арминга; замена аккумулятора между попытками; запуск
службы штатной командой (шаг 4). До шага 5 борт не обесточивается.
